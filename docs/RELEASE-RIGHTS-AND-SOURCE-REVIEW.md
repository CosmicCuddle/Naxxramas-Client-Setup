## Material rights questions identified

### Required and optional MPQ patches

The [patch repository](https://github.com/CosmicCuddle/Naxxramas-Server-Patches) publishes assets and documents their intended client effects but does not publish an identified asset-by-asset distribution permission for the setup application. The patch README recognises World of Warcraft artwork/assets as belonging to Blizzard Entertainment and states no affiliation. An acknowledgement is **not** a copyright licence.

- Patch-J advertises Vanilla-style login visuals, replacement music and additional loading-screen assets. Review **each** work's origins, licence and whether bundled setup redistribution is permissible.
- Patch-C advertises Burning Crusade-style login visuals, Dark Portal/Hellfire assets and replacement music. The same questions remain.
- Patch-U credits **slendydaddy** for HD Vanilla loading-screen artwork. Crediting an artist does **not** establish that the installer may repack or redistribute the files.
- Required V and Z carry custom client data, but a published MPQ digest and a first-party GitHub release do not prove the source, permitted use and downstream redistribution terms of every contained DBC, model, texture, sound or other client asset.

Do **not** copy the MPQ files into the scripts-only candidate, enable a download/install action, or infer rightsholder permission from public GitHub hosting.

### N Addon Suite v2.0.0 (five installed folders)

The [tagged source lock](https://github.com/CosmicCuddle/N-Addon-Collection/blob/v2.0.0/sources.lock.json) identifies five original snapshots, and the suite build embeds Classic Battlegrounds inside NCore. The five *installed* roots are `NCore`, `IndividualProgressionAddon`, `DungeonJournal`, `MultiBot` and `NaxxLootLottery`. `NClassicBattlegrounds` is a source snapshot but is **not** a sixth installed root. Talent Calculator is not part of v2.0.0.

**Important Dungeon Journal finding:** its own CREDITS explicitly calls some Blizzard model renders and world-map art **not covered by the GPL**. Copying `LICENSE-GPL-2.0.txt` and `CREDITS.txt` into the ZIP preserves useful attribution but does **not** settle the separate artwork permissions. Other Atlas-related material also requires a per-origin review.

The GPLv2/GPLv3 texts in **separately distributed addon components** do not, by their mere coexistence in a ZIP, prove an incompatibility; nor do they automatically establish compatibility if code is actually combined. Assess the real packaging/source relationships and relevant licence versions before deciding any combined-work questions. Avoid inventing a blanket licence for the five-folder suite. The collection's own [README](https://github.com/CosmicCuddle/N-Addon-Collection/blob/v2.0.0/README.md) states that each addon retains its original licence and credits.

A GitHub API `license: null` result or absent root `LICENSE` does **not** prove a work has no copyright, nor that a permissive licence applies. Permissions may be stated elsewhere or require confirmation.

## What can advance next — separate owner decisions

1. **Create an owner-approved rights inventory for every binary resource.** For each patch, list input asset, upstream author/rightsholder, exact provenance, applicable licence/permission, modification status and whether repackaging by the setup application is authorised. Record specific documents or direct authorisation—**not** just a GitHub URL or credit.
2. **Finish addon third-party obligations.** Preserve GPL licence texts and complete source/credit notices; reconcile the actual released ZIP's contents with pinned source tags and each component's third-party libraries/art. Resolve any potential combined-work implications explicitly.
3. **Decide distribution scope** separately for (a) script-only review, (b) displaying upstream download links, (c) downloading files on behalf of a player, (d) redistributing a combined installer/client image and (e) actual installation. Permission for one scope is not permission for another.
4. **Keep security and recoverability independent of rights.** A legally permissible package still requires protected original backups, all profiles' WTF settings, external recovery authority, atomicity/crash testing and a separate explicit user-consent design.
5. **Complete physical Windows and in-game testing**, including 100/125/150/200% scaling, High Contrast, keyboard, screen-reader and actual gameplay, before any release-readiness decision.

## Machine-readable regression gate

The conservative [rights evidence snapshot](release-rights-evidence-v1.json) records **five patch resources and five installed addon folders** with `redistribution_cleared=false`, `installation_approved=false` and `public_release_authorised=false`. It is an inventory, **not** a signed licence, rights database or judgement by counsel.

The Windows/Linux workflow exercises rejection of a silently flipped flag or omitted asset. No downloads, personal data, legal-permission verification, client files or write-capable implementation are involved. Any **future** verified change would require a deliberate, independently reviewed policy and test update.

**Decision:** continue source-only work and separately permitted technical QA. **No file redistribution, player installation, real backup/recovery operation or public client setup release is approved by this milestone.**
